# Feature icons

Our features' icons follow Onshape's own, so they sit naturally in its feature list: they're drawn from shapes in
Python (`fs_cli/icons.py`, with shapely), generated by `fs gen`, and compared side by side with `fs icons`.

## Onshape's style

Onshape's feature icons (in `onshape_icons/feature/`, to compare with) are 20 units square, shown at 20 px:

- An oblique view: the face toward you, with what's behind it going back up and to the left.
- A heavy #333 outline (about 1.3 units), with faces inset inside it.
- Colors, as Onshape names them: #333 (`OUTLINE`) for outlines, and the openings you see through; #999 (`FACE`) for
  the face toward you, or what a feature adds (Rib's rib, the inside of Shell's shell); #D7D7D7 (`SIDE`) for faces
  going back; white (`WHITE`) for sketch faces, and for parts in Rib and Shell.
- Cuts through a face (holes, pockets) as the plate icon (`featurescripts/plate/Plate_v2.svg`) draws its holes: a dark
  rim, and inside it, the wall you can see (#999, on its lower right, as the cut goes back up and to the left) and the
  dark opening at its back.
- Few details: what reads at 120 px can be a smudge at 20 px, especially on Onshape's dark theme.

More of Onshape's icons are in its icon sprite, which its sign-in page links (`https://cad.onshape.com/signin`, then
e.g. `https://cad.onshape.com/images/icons.v1.4.428.min.svg`; neither needs signing in): each is a `<symbol>` with an
id like `svg-icon-rib-button`. Save one as `onshape_icons/feature/<name>.svg` (its symbol's contents in an `<svg>` with
its `viewBox`), and run `uv run python onshape_icons/make_index.py`.

## Drawing one

An icon definition is a Python file beside its feature, named like the icon (`lighten/robotLightenIcon.py`), which
sets `ICON` to an `Icon`; see `featurescripts/lighten/robotLightenIcon.py`. Shapes are shapely geometry in the icon's
units (y down, as in SVG), so they combine (`union`, `difference`), offset, and move freely. `fs_cli/icons.py` has:

| Function | What it does |
| --- | --- |
| `rounded_rectangle`, `circle` | Shapes to start from |
| `offset(shape, distance)` | Grows a shape (or shrinks it, negative): a wall of one thickness everywhere is an offset |
| `round_corners(shape, radius)` | Rounds its convex corners, as a router bit cuts a pocket's |
| `back(shape, depth)`, `sweep(shape, depth)` | A shape moved back (up and to the left), and everything it covers on the way |
| `Icon().fill(shape, color)` | A shape in a color |
| `Icon().outlined(shape, color)` | A shape with Onshape's outline |
| `Icon().extrusion(front, depth)` | A solid: its front face, white, and its sides going back, #D7D7D7, outlined |
| `Icon().through(outline, depth)` | A cut through a face, its outside edge `outline` (as above) |

Then:

```
uv run fs gen                                     # writes the .svg beside the definition (no API calls)
uv run fs icons featurescripts/plate/Plate_v2.svg featurescripts/lighten/robotLightenIcon.svg -o icons.png
```

`fs icons` saves a picture of icons side by side: each big, and at 20 px on light and dark. Put a few variations (and
the icons they're based on) in one picture to choose between: write each to its own file while trying them. Paths are
simplified to within 0.02 units, which keeps an icon around 10 KB; check that `fs gen` hasn't made one much bigger.

A feature imports its icon by path until it's pushed (see README's "Images"):

```
RobotLightenIcon::import(path : "lighten/robotLightenIcon.svg", version : "");

annotation { "Feature Type Name" : "Robot lighten", "Icon" : RobotLightenIcon::BLOB_DATA }
```

and `fs push` (with the user's say-so) uploads it and resolves the import. Mention the icon in the feature's writeup
(its files table). Tests check generated icons are up to date, like other generated files.

## Lessons

From Robot lighten's icon, which went through a dozen versions:

- Start from one of ours or Onshape's: a pocketed version of the plate icon read as "lightened" at once, where a new
  shape needed explaining.
- Walls of one thickness look deliberate: offset the outline and the holes by the wall, rather than placing shapes by
  eye. A hole centered on a rounded corner gets a wall which follows the corner.
- Round where walls meet (`round_corners`); too much rounding turns a pocket into a blob.
- Thin sides (a plate's thickness under 2 units) disappear at 20 px, and so do pockets under about 2 units across.
